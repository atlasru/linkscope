# Legacy audit and replacement rationale

Inspected 16 October 2026. The preserved `legacy/` source is a reference implementation, not the foundation of the replacement. This review is based on source inspection; historical CI claims in its documentation are not new validation.

## Repository and preservation

The new working directory initially had no Git metadata. The parent implementation is retained under `legacy/`, including its Git metadata. The adjacent `../linkscope/` directory has source/build artifacts but no `.git` directory, so its changes cannot be classified as committed or uncommitted. No files there were changed.

A normalized text comparison (ignoring CRLF versus LF) finds these differences between the preserved source and the adjacent source: `README.md`, `.github/workflows/check.yml`, `crates/core/src/{storage,transform}.rs`, `crates/core/tests/core.rs`, `docs/{acceptance,verification}.md`, `src-tauri/tauri.conf.json`, `src-tauri/src/main.rs`, and `ui/{app,renderer}.js`. The preserved version also has the Canvas fallback, two WebGL regression scripts, bundle icons, and an extra build workflow. The adjacent directory contains dependency locks, a bundled HTML preview, `node_modules/`, and `target/`. These independent artifacts should remain recoverable, even when they predate fixes in the preserved version.

The preserved implementation contains fixes absent from the adjacent source: Windows transaction-tail repair uses a writable file handle; transform futures are explicitly `Send`; the GLSL input `active` was renamed to `isActive`; renderer startup failures no longer prevent all UI handlers from registering. These regression cases are useful test inputs for the replacement.

## Findings by boundary

| Area | Evidence and consequences |
| --- | --- |
| Core model | `crates/core/src/model.rs`: node identity is UUIDv5 of `kind:value`, with automatic domain/email normalization and merging. Two records with equal text cannot remain separate hypotheses. Renaming a value does not have a defined stable identity contract. The fixed confidence ladder embeds an investigation-specific classification in every node. Edges have one provenance string, no arbitrary properties, and directed topology only. There is no project-level schema, collection model, annotations, or explicit identity resolution. |
| Graph and memory | `graph.rs`: `StableDiGraph<HotNode, String>`, string-ID hash map, and a second edge-ID hash set duplicate identifiers. Payload eviction leaves all topology resident. The budget is a JSON-size heuristic, not process memory measurement. Admission estimates incoming objects even for updates and evicts cached payloads before the durable mutation succeeds. Endpoint validation scans `batch.nodes` repeatedly. Public `apply` relies on callers to validate and can panic on unknown endpoints. |
| Engine | `engine.rs`: a bounded queue and dedicated graph/store thread are good ownership choices. However storage, topology, search, cache, and long exports share the same worker. Startup reconstructs all topology and an in-memory search index before the app opens. There are no reversible commands, deletes, undo/redo, or graph change events. |
| Frontend | `ui/app.js` is a monolithic plain-JavaScript event/controller/view module with global mutable state. `model.js` duplicates topology and presentation records and recreates complete position/link typed arrays. No strict TypeScript contract checks the Rust boundary. The UI is an OSINT dashboard with permanent counters, activity, legend, timeline, and explanatory text; fixed-width panels cannot be resized or persisted. |
| IPC | `src-tauri/src/main.rs`: startup pages complete JSON records through IPC, then keeps the whole topology in JS. Successful transforms return full batches; each refresh rebuilds arrays, metadata, neighbor textures, and all GPU buffers. Layout persists positions in many batches, rewriting full node JSON and adding a durable intent record per batch. Polling runs every 150 ms even when idle. Small changes lack an explicit revision/delta protocol. |
| Rendering | `ui/renderer.js`: custom WebGL2 points/lines make few draw calls but always submit the complete graph. There is no spatial index, viewport query, edge geometry for parallel relationships, direction marker, or meaningful label LOD. Selection uploads all metadata. Picking scans every node and may synchronously read all GPU positions. Context loss requests reload. |
| Layout | The GPU shader uses at most four adjacent nodes and eight deterministic repulsion samples. This is a bounded approximation, not a complete force-directed algorithm; neighbor order changes its result. Synchronous GPU readback and full-node position saving follow layout. `community.js` builds a separate array of maps in a Worker, raising memory usage substantially at large scale. |
| Fallback | `fallback-renderer.js` retains camera/picking while `app.js` draws Canvas overlays. Painting is capped to the first 3,000 nodes and 5,000 edges, irrespective of viewport. Later nodes can be picked but never painted. Layout is disabled. This is useful startup degradation, but not an equivalent, scalable editing path. |
| Persistence | `storage.rs`: SQLite WAL/full sync plus a checksummed, idempotent intent journal and exclusive folder lock are sound recovery concepts. The journal and applied-ID table grow without checkpointing. Every node mutation serializes full JSON. There is no schema version/migration chain, named project lifecycle, portable reopen flow, or atomic workspace/settings save. Configuration writes directly to the final file. A corrupt complete journal line blocks startup with a generic error. |
| OSINT | `transform.rs`/`network.rs`: typed async trait, declared input type/host, bounded response body, timeout, cancellation, concurrency cap, per-source gates, TTL cache, and disabled-by-default external access are reusable policies. They are coupled to engine commits and stringly typed parsers. Discovery outputs are automatically merged by deterministic identity and use generic `observed` edges. RDAP always addresses the `.com` registry regardless of domain suffix. A source name is not sufficient claim-level provenance. |
| Import/export | `export.rs`: streaming exports avoid a second full graph copy. JSON import exists only as a small batch parser; it is not exposed as a complete UI import workflow. CSV, conservative text preview, explicit mapping, original-record preservation, merge/split, and reconciliation are missing. STIX/MISP serializers have no external format validation evidence. |
| Platforms | `main.rs` uses Unix-shaped home subdirectories on every platform instead of platform app-data paths. Windows WebView2 installation is skipped in bundle settings. Windows RSS is unavailable; Linux samples only the backend process. The preserved Windows journal fix should be retained as a regression test. Native application launch, recovery across processes, DPI, keyboard behavior, and WebGL driver compatibility still need direct testing. |
| Tests/debt | Thirteen Rust tests cover identity, dangling edges, budget rejection, duplicate batches, journal recovery/corruption, cache expiry, route validation, payload reload, DNS parser, exports, vault, and scheduler spawnability. JS tests cover fixtures/hulls/community and shader/fallback regression checks. Browser scripts are useful but their dependencies are not declared, and `npm test` runs only `model.test.mjs`. There are no editor history/import/project interaction tests, timeout/rate-limit integration tests, native GUI test evidence, or measured end-to-end 100k/500k benchmark. Source is densely compressed, increasing review cost. |

## Discard, retain, redesign

Discard the OSINT-first identity/merging model, fixed confidence taxonomy in graph storage, dashboard shell, full-state refreshes, GPU-owned layout truth, global implicit investigation directory, unbounded dual journal, and any performance assertions derived only from the frontend fixture generator.

Retain the MIT attribution, relevant parser fixtures, explicit-network-action principle, bounded asynchronous jobs, recovery regression scenarios, streaming-export idea, and small desktop capability surface. Reuse policies after testing their contracts; do not copy dependency-heavy subsystems merely because they already exist.

Redesign around a generic Rust property multigraph with opaque stable IDs; typed JSON properties on entities and relationships; explicit directed/undirected semantics; structured provenance; project metadata, collections and annotations; validated atomic bulk patches and reversible history. OSINT services produce proposed generic patches with attribution. Import parses into the same contract and requires review of ambiguous text extraction. Identity merging is an explicit user action.

## Replacement architecture and tradeoffs

1. **Rust core** owns validation, graph mutation/history, import, persistence, background computation, and service execution. Separate library modules stay independent of Tauri and rendering. Use sparse identifier indexes plus adjacency references and benchmark real memory; defer an arena/CSR rewrite until measured workloads justify it.
2. **Tauri 2** remains a reasonable shell: native filesystem access and long-running work remain behind narrow commands, with no account or server requirement. Its system WebView and Windows toolchain are explicit compatibility dependencies. Electron offers a consistent Chromium renderer but adds distribution/runtime overhead; a native GPU UI removes the WebView but substantially increases accessible editor/UI work. Neither alternative earns that cost for this vertical slice.
3. **Strict TypeScript editor** owns transient gestures, camera, selection, panel geometry and a render projection. Keep domain mutations behind one typed API and propagate changed/deleted IDs with revisions. Coalesce one drag into one undo entry; do not persist every pointer movement. Avoid placing the full graph inside a reactive component tree.
4. **Renderer boundary** accepts only visible geometry and presentation state. Start with a tested Canvas 2D implementation using spatial candidates, node/edge budgets and label LOD. A WebGL2 backend can share that projection after measurements justify it. Canvas compatibility takes priority over requiring WebGL2. At extreme zoom-out, aggregated/sampled display must be explicit; stored records must remain searchable and editable. A budget is not proof of smooth full-graph rendering.
5. **Portable versioned projects** use atomic replacement, recoverable prior generations and explicit schema migration. Keep the working graph in memory and debounce saves. SQLite becomes useful when measured update/recovery or file-size costs justify it; avoid adopting both a database and a second unbounded journal by default.
6. **Async transforms** declare input types and output schema, timeout, rate limit, concurrency and cache policy. A test transport verifies cancellation and scheduling without accessing remote services. Live DNS/RDAP/certificate checks remain separate opt-in validation and preserve exact request/source/time attribution.

## Upstream research

Checked primary upstream sources on 16 October 2026:

- [Cytoscape.js performance documentation](https://js.cytoscape.org/#performance): batching, label suppression, simpler edges, and reduced pixel ratio are important even in a mature editor. It offers rich editing features, but its documentation does not establish the required 100k/500k workload. It is an alternative to benchmark, not an automatic scalability solution.
- [Sigma rendering documentation](https://www.sigmajs.org/docs/advanced/renderers/): a dedicated WebGL graph renderer is a viable future backend; adopting one still requires a separate editable domain graph, worker layout and a tested fallback.
- [tldraw editor source](https://github.com/tldraw/tldraw/blob/main/packages/editor/src/lib/editor/Editor.ts): reviewed interaction history stopping points, batches and spatial-candidate picking. These are useful patterns for reversible direct manipulation; its entire editor/store is unnecessary for LinkScope's graph domain.
- [Tauri IPC documentation](https://v2.tauri.app/concept/inter-process-communication/): commands are the request/response boundary. Domain-independent library tests should exercise the same contracts before the desktop shell is involved.

These are design references, not copied source or benchmark evidence.

## Implementation order

First establish a buildable shell and core contract, then editing/history and project recovery. Validate a real create/connect/drag/delete/undo/save/reopen vertical slice before expanding import and transformations. Add conservative import preview and deterministic service fixtures. Finally benchmark reproducible backend and visible-scene workloads separately, profile, and document remaining limitations. Native Windows build/run and WebGL-disabled behavior are distinct required checks.
